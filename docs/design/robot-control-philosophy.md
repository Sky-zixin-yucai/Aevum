# 机器人控制的设计哲学与工程经验

最后更新：2026-11-26

适用范围：Aevum 机器人内核、身体描述、几何控制能力、通用动作机制。

## 一、一句话结论

外部提供身体（参数描述），内核提供几何类别的原生控制能力，动作是几何类别参数空间里的实例；**内核不是动作库**。

## 二、三层边界

| 层 | 负责 | 不负责 |
| --- | --- | --- |
| 身体 | 自己的形态、运动学、动力学、本地伺服、通道映射；用参数描述自己 | 不要求内核知道自己是什么物种 |
| 内核 | 几何类别生成器、控制通道读写、周期、限幅、饱和、故障、状态 | 不保存动作表，不解释“抓取/行走”等语义 |
| 外部 | 选择动作实例、填写几何/运动参数、编排序列 | 不要求内核为每个动作写代码 |

关键点：身体给的是**完整身体信息**，不是给内核一份“我是麋鹿/我是机械臂”的语言说明书。内核只需要能感受这份信息并完成控制。

## 三、几何能力分类

数学已经分好类，不自己另造。能力按**类别**建，不按实例建：

- 0D：点
- 1D：线段、圆弧、圆
- 2D：多边形 `POLYGON(n)`、圆盘、平面
- 3D：多面体、曲面、体

三角形是 `POLYGON(3)`，四边形是 `POLYGON(4)`，不是两个独立能力；圆是常曲率闭曲线，不属于多边形族；平面是二维仿射子空间，不是“边数很多的 polygon”。

实例无限，能力族有限。

## 四、动作如何产生

- 一个几何类别 = 一个参数化生成器。
- 一个动作 = 该生成器参数空间里的一个实例。
- 参数分三类：
  - 几何参数：边数、顶点、半径、平面基等；
  - 运动参数：起点、方向、速度、时间等；
  - 约束参数：限位、速度上限、故障边界等。
- 内核只实现生成器；不为每个动作写代码，不建动作库。

“无限衍生”要区分两种：

- **参数化衍生**：有限生成器 + 连续参数。内核轻，推荐。
- **程序化衍生**：任意组合、条件、循环、序列。需要描述语言解释器，复杂度高，容易退化成脚本引擎。

本项目采用**参数化衍生**。

## 五、设计判断

1. **不批量实现所有几何。** 建模没准备好就不写；一个模型一个模型来。
2. **不用 `class_id` / 固定能力表做路由。** 内核拿完整身体信息，按当前身体参数执行。类别信息由身体信息本身表达，不是查一张预置表；具体字段等建模确定。
3. **当前 2–8 关节平面串联链实现已经证明这条路径。** 建模改变、关节变多，动作描述的数组和执行跟着变。这是现有基础，不推翻。
4. **同一个几何类别可以描述身体形态，也可以描述末端轨迹。** 参数表要区分 `body` 和 `path`，不能混用。
5. **内核不保存 `MoveJ` / `Dwell` 这类动作语义。** 这些是外部对参数实例的命名，不是内核能力。

## 六、实现顺序

1. 建模先行；未完成建模的几何不进入实现。
2. 只针对该模型调试它的动作几何衍生生成。
3. 不预写其他几何，不先搭空框架。
4. 每完成一个模型，记录：身体参数、几何类别、动作参数、控制结果、页面/测试证据。

## 七、工程经验

1. **先定契约，再写实现。** 先把“身体提供什么、内核生成什么、动作参数是什么”对齐，再进入代码；概念没对齐时，代码越写越像动作库。
2. **区分机制与演示。** 三角波、测试轨迹、示例页面都是验证手段，不是通用机制本身；不能把演示参数固化成内核语义。
3. **不要把策略库塞进内核。** 固定 `MoveJ`/`Dwell` 类型、固定动作队列、固定动作页，都是动作库的雏形；内核只保留几何能力生成器和执行约束。
4. **能力按类别和参数化族实现，不按实例枚举。** 三角形、四边形是 `POLYGON(n)` 的参数，不是新能力；否则能力数量会随实例无限膨胀。
5. **建模先行，一次一个几何。** 未建模的几何不提前实现；每完成一个模型，再调试它的动作衍生。
6. **接口数据化。** 身体参数、动作参数、状态都应是数据；内核不解释“抓取/行走/麋鹿”等语义。
7. **变更要有可复现证据。** 代码变更应附构建、测试或页面证据；设计文档与代码同步更新，避免文档描述落后于实现。
8. **文档分类清楚。** 设计思想、设计判断、实现顺序、工程经验分开写，方便评审、检索和后续扩展。

## 八、与当前代码的关系

- `body_desc` 的 2–8 关节参数化执行是已验证的基础，保留。
- 内核当前没有 `MoveJ`/`Dwell` 动作队列，也没有动作页；动作库方向的未提交实现已撤回。
- Forge 的 `SWEEP` 与 3R `GRAB` 是宿主侧的参数实例：`SWEEP` 只生成 J1 的正弦目标，`GRAB` 只做一次 3R IK 并把关节目标写成普通 `J` 命令；内核不保存这两个名字，也不认识“抓取”语义。
- Forge 场景里的方块是 `doc.prop`，属于宿主演示对象，不是 `body_desc` 的一部分；抓取闭合与方块跟随是渲染层演示，不是内核能力。
- 后续实现应按“几何类别生成器 + 参数实例”扩展，而不是继续往 `control.c` 里堆动作类型。
- 在建模和几何顺序确定前，不预先实现三角形、四边形、圆、平面等其他能力。

## 九、术语

- **身体描述**：身体自己给出的完整控制参数，不是内核预置的身体模型。
- **几何能力**：内核针对某个数学几何类别的原生控制生成能力。
- **动作实例**：几何能力参数空间中的一个具体取值。
- **参数化衍生**：用有限生成器 + 参数产生无限动作实例。
