# 玩具越野车：模型格式、内核在环 3D 联调与硬件顺序

最后更新：2026-11-27

适用范围：玩具越野车的 3D 外观建模、模型格式、模型加载、内核在环 3D 世界联调、硬件接入与验收。

本文档面向 Aevum 开源项目的维护者、贡献者和使用者，不按个人对话写。本文档是控制契约，不是实现完成证明。车辆与机械臂的 glTF 生成器、校验器、测试和占位模型已经落地；Forge 已默认加载 `toy_offroad` 并做通用模型查看，车辆的内核在环控制与执行器通道尚未实现。

## 一、顺序

上一版把“完全不做仿真”写成绝对禁令；按项目当前要求改：**允许并且要求“内核在环的 3D 世界联调”**，禁止“无内核的本地仿真”和“仿真兜底”。

建模不是只摆着看。模型做完，就要让内核控制它在 3D 世界里跑起来；联调效果像玩汽车游戏，才允许接硬件。

1. **本文档**：定顺序、模型格式、控制契约、联调门槛和验收。
2. **玩具越野车 3D 外观模型**：静态几何 + 模型格式 + 保存/加载。
3. **内核在环 3D 世界联调**：内核控制模型，模型在 3D 世界里像车一样动。
4. **联调验收**：转向、驱动、停车、复位、状态回传都从内核来，不从页面本地控制来。
5. **硬件接入**：联调验收通过后，才接真实车。
6. **实车验收**：真实控制链路上的直线、转向、停车和故障。

没有模型格式，不进入联调；没有内核在环联调验收，不接硬件；没有硬件，不做实车验收。

## 二、旧格式是什么关系

机械臂和车辆的**源模型文件**都是 glTF/GLB；Forge 的 Import 接受 `.glb`，或 `.gltf` + `.bin`。

导入后，Forge 在内部生成 `BodyDocument`：

| 文档 | 用途 | 是不是模型文件格式 |
| --- | --- | --- |
| `aevum.body/0` | 原生 3R 平面链回退文档 | 不是；内部工作文档 |
| `aevum.body/1` | glTF/GLB 导入后的 link/joint 树 | 不是；内部工作文档 |

对应代码：

- `interface/web/forge/js/model/body-document.js`：内部文档 schema、默认文档、校验、`body descriptor`。
- `interface/web/forge/js/model/gltf-loader.js`：`.glb` / `.gltf` → 内部文档，保留 `asset.extras.aevum` 与节点 `actuated`。
- `interface/web/forge/js/model/catalog.js`：已入库模型与 URL 加载。

关键：**模型文件格式是 glTF 2.0；`aevum.body/0`、`aevum.body/1` 是 Forge 的内部文档，不是源模型格式。** 页面不再提供 `Save JSON` / `Load JSON`，也不把内部 JSON 当模型交付格式。

## 三、模型格式：glTF 2.0（车辆与机械臂共用）

模型文件是 `.gltf` 或 `.glb`，标准 glTF 2.0。

- 几何、节点、材质、缓冲都在 glTF 里；
- 车辆参数放在 `asset.extras.aevum`；
- 节点角色放在 `node.extras.aevum`；
- 这是 glTF 的 `extras`，不是另起一套模型格式；
- 不再使用 `aevum.body/2` 自定义 JSON；之前那个方案已撤。

坐标约定：

- `x`：向前；
- `y`：向上；
- `z`：向右；
- 地面是 `x-z` 平面；
- 轮子位置是 `[x, 轮半径, z]`；
- 转向轴是 `y`，车轮滚动轴是 `z`。

车辆参数至少包括：

- `chassis`：车长、车宽、车高、轴距、轮距、离地间隙、质量；
- `wheels`：轮子 id、转向 node、滚动 tire node、位置、半径、宽度；转向/驱动只由 `joints` 表达，不在轮子上重复标记。前轮的 `node` 是 steer 枢轴，`tire` 是它的滚动子节点；后轮两者同为轮节点；
- `joints`：转向/滚动关节、轴、限位、通道；
- `control`：100 Hz、dt、通道、限位、超时；
- `sensors`：有没有轮速/转向反馈。

示例只列 `asset.extras.aevum` 的关键字段，不是完整模型文件：

```json
{
  "kind": "vehicle",
  "placeholder": true,
  "units": "m",
  "chassis": {
    "length": 0.32,
    "width": 0.18,
    "height": 0.10,
    "wheelbase": 0.22,
    "track": 0.18,
    "ground_clearance": 0.03,
    "mass": 0.8
  },
  "control": {
    "loop_hz": 100,
    "dt": 0.01,
    "channels": { "steer": ["steer_fl", "steer_fr"], "drive": ["spin_rl", "spin_rr"] },
    "limits": { "steer": 0.6, "speed": 1.0, "timeout_ms": 200 }
  },
  "sensors": { "wheel_speed": false, "steering": false }
}
```

规则：

- 模型文件是 glTF，不把车壳写死在代码里；
- 车辆参数从 `asset.extras.aevum` 读，不从自定义 JSON 读；
- 加载器把 glTF 和 `extras` 转成内核能接收的通用描述；内核不按车型写分支；
- 保存就是保存 glTF；导入就是读 `.gltf` / `.glb`，不是现场用代码拼一辆车；
- 现在占位模型的缓冲内嵌在 `.gltf` 的 data URI 里；以后可以换成外部 `.bin` 或 `.glb`。

### 机械臂模型

默认 3R 机械臂走同一套格式，不另写自定义 JSON：

- `body.base`：基座 `0.54 × 0.24 × 0.38 m`，质量 2.2 kg；
- `body.links`：三节连杆，长度 `0.62 / 0.52 / 0.24 m`，每节带 `dynamics`（torque / inertia / damping / kp / kd），沿用 Forge 默认值；
- `body.tool`：工具长 0.20 m；
- `joints`：三个 `revolute` 关节，限位按 Forge 默认：J1 ±170°、J2 ±150°、J3 ±170°，home `1.05 / -1.60 / 0.55 rad`；
- `control`：100 Hz，单个 `joint` 通道；
- 文件：`interface/web/models/arm/arm3.gltf`。

### 一万个模型的目标

内核适配一万个不同形态的模型，不是写一万套代码，而是：

- 同一内核二进制，换 glTF 模型，不重编译；
- glTF `extras` 描述尺寸、轮子、关节、通道、限位；
- 加载器负责校验和转换；内核只认通用描述；
- 批量加载、批量联调、批量记录。

这是长期目标，不是当前完成度。当前有 2 个占位 glTF 模型（车辆和 3R 机械臂），Forge 已默认加载车辆并支持模型目录与通用导入；车辆的内核执行器通道与 3D 被控对象还没有接。

### 生成代码职责唯一

模型生成代码拆成五层，一层只做一件事：

| 层 | 文件 | 职责 |
| --- | --- | --- |
| 生成 CLI | `interface/web/models/generate.js` | 按模型名调用 build、写文件、打印摘要；不认几何和关节 |
| glTF 结构 | `interface/web/models/gltf/gltf-builder.js` | box/cylinder primitive、material/node、buffer、accessor、mesh、scene |
| 公共 extras | `interface/web/models/gltf/model-meta.js` | `schema`、`kind`、坐标、公共 joint、control 通道引用、node role、sensors |
| 车辆语义 | `interface/web/models/vehicle/vehicle-model.js` | 车身尺寸、四轮、转向/驱动关节、车辆通道 |
| 机械臂语义 | `interface/web/models/arm/arm-model.js` | 基座、连杆、工具、3R 关节、机械臂通道与 dynamics |

规则：

- glTF 结构和公共 extras 只有一份，车辆与机械臂都调用它，不复制 buffer/accessor 代码；
- 生成 CLI 只有一份，不按模型各写一个脚本；
- 车辆模型不写机械臂字段，机械臂模型不写车辆字段；
- 测试只测各自模型语义；
- 新增车型或新机械臂只加语义数据，不复制生成代码。

当前已落文件：

- `interface/web/models/generate.js`
- `interface/web/models/gltf/gltf-builder.js`
- `interface/web/models/gltf/model-meta.js`
- `interface/web/models/gltf/gltf-builder.test.js`
- `interface/web/models/vehicle/vehicle-model.js`
- `interface/web/models/vehicle/vehicle-model.test.js`
- `interface/web/models/vehicle/toy_offroad.gltf`
- `interface/web/models/arm/arm-model.js`
- `interface/web/models/arm/arm-model.test.js`
- `interface/web/models/arm/arm3.gltf`

当前统计：

- `toy_offroad.gltf`：36 nodes / 8 meshes / 792 triangles / 6 关节；车身、车顶、车窗、灯、保险杠、轮眉和行李架都是静态 part。前轮是 `steer` 枢轴 + `drive` 轮胎两级，后轮直接 `drive`，四个轮毂跟随轮胎。
- `arm3.gltf`：5 nodes / 5 meshes / 60 triangles / 3 关节。

生成与测试：

```bash

node interface/web/models/vehicle/vehicle-model.test.js
node interface/web/models/arm/arm-model.test.js
```

只生成一个模型时，在 `generate.js` 后面加 `vehicle` 或 `arm`。

## 四、内核在环 3D 世界联调

### 1. 3D 世界是什么

3D 世界负责两件事：

- **被控对象**：按内核下发的执行器通道，让模型产生车辆运动；
- **呈现**：相机、车身、车轮、地面、HUD、回放。

3D 世界**不负责控制**：不自己算转向/油门，不自己决定目标，不在内核掉线时接管。

当前 Forge 只完成“呈现 + 模型加载 + 内核状态桥接”这一段：默认加载 `toy_offroad.gltf`，只绘制静态模型和 6 个轮关节（前轮转向 + 四轮滚动），不积分车辆运动，也不跑本地 PD。车辆的执行器通道映射和内核在环被控对象属于下一阶段。

### 2. 控制链

```text
键盘/手柄/动作参数
  -> 宿主只传参数
  -> 内核控制任务（100 Hz）
  -> 通用执行器通道
  -> 3D 世界被控对象
  -> 模型运动 + 状态
  -> 内核状态/遥测
  -> HUD / 曲线 / 记录
```

内核在环，页面不在环里做控制。3D 世界可以积分车辆运动，因为它是被控对象；但它不能替代内核的控制计算。

### 3. 像玩汽车游戏

联调必须做到：

- 模型从文件加载，不是代码里拼出来的；
- 相机跟随、车身姿态、车轮转向/滚动看得见；
- 键盘或手柄能控制前进、后退、转向、停车；
- HUD 显示内核链路状态、控制周期、通道指令、模型状态；
- 松开输入能停，断链能停，复位能回初始位；
- 整个过程中，转向/驱动指令来自内核，不来自页面本地控制器。

不是“放一段动画像车在跑”，而是“内核在控制这辆车”。

### 4. 联调通过才接硬件

联调验收不通过，不接真实车。联调通过只证明“模型 + 内核 + 3D 被控对象”这条链路，不证明真实舵机、电调、供电和机械间隙；实车还要单独验收。

## 五、内核控制契约

### 1. 控制权归内核

- 控制周期、指令生成、限幅、故障和状态由内核控制任务负责。
- 页面、3D 外观模型、宿主演示只负责参数下发、呈现和记录，不逐周期计算转向/油门。
- 页面不能发假状态，不能在内核掉线时用本地控制兜底。

当前内核已有 100 Hz 控制任务节拍；车辆控制沿用这个固定周期，不先承诺 1 kHz。以后要改周期，必须用真实硬件测周期和抖动。

### 2. 输入

身体参数来自模型文档：

- 轴距、轮距、轮半径、离地间隙；
- 转向范围、驱动范围、速度上限；
- 执行器通道映射、转向方向、死区；
- 有没有轮速/转向反馈。

动作实例来自外部：

- 几何：`LINE` 的两个端点，或 `ARC` 的圆心、半径、起始角、带符号扫角，平面 `(x,z)`；
- 运动参数：速度、持续时间、到位容差；
- 约束：速度上限、转向限位、超时。

`LINE` 提供 1D 有界直线几何：端点、长度、方向、归一化 `t`、投影。`ARC` 提供 1D 有界圆弧几何：圆心、半径、起始角、带符号扫角、长度、切向和曲率。`t` 是弧长参数，不是时间。速度和时间是动作实例的运动参数，不写进几何。

`ARC` 的曲率按车体 `yaw` 对弧长定义：正扫角 `kappa=-1/r`，负扫角 `kappa=+1/r`。前轮转角由身体参数里的轴距换算 `atan(wheelbase * kappa)`，这只是身体层映射，不是内核里的车辆动力学。

当前 `LINE` 和 `ARC` 已接入内核 Makefile、UART 通用 `P` 命令和 `0x05` 路径状态帧，并在 Forge 上完成 0.40 m 直线与 90° 圆弧验收：内核按 100 Hz 推进 `s`，输出路径点、切向和曲率，页面只呈现位姿、前轮转角和轮子滚角，不本地积分。`CIRCLE` 连续多圈尚未实现。

### 3. 内核每周期做什么

1. 校验身体参数和动作参数；退化线段、`t<0`、`t>1`、超限速度直接拒绝。
2. 按固定周期推进弧长：`s += v * dt`，再算 `t = s / L`。
3. 用 `LINE`/`ARC` 几何算出当前路径点 `(x,z)`、单位切向和曲率。
4. 把路径点、几何误差和通用通道量交给身体层；由身体层按自身运动学/本地伺服映射成转向、驱动等执行器通道。
5. 执行限幅、饱和、超时和故障处理。
6. 输出通用状态：周期号、`s`、`t`、路径点、通道指令、反馈（如果有）、故障码。

内核不保存动作表，不认识“玩具车”“直线运动”“转向”“油门”这些语义；这些名字属于外部或身体层。内核只认几何参数、运动参数、约束参数和通用通道。

### 4. 身体层做什么

身体层是实际硬件适配，也是 3D 世界被控对象的接口，不是控制替代品：

- 把通用通道量映射到转向舵机、电调/电机；在 3D 世界里映射到模型关节/轮子；
- 处理转向方向、死区、最小值/最大值；
- 有反馈就回传实际轮速/转向；没有反馈就明确标注“仅指令，无反馈”；
- 身体层可以放在内核侧或控制板侧，具体位置在身体参数建模时定，但不能放在页面里做“看着像”的运动。

### 5. 明确禁止的旧方案

- 不在内核里写固定自行车动力学 `vehicle.c`；
- 不新增车辆专用 `C` 命令；
- 不新增 `0x04` 车辆状态帧；
- 不把 `throttle/steer/brake` 写成内核语义；
- 不让页面键盘直接驱动车辆而不经过内核；
- 不让宿主本地物理积分冒充内核控制；
- 不用固定动作表或 `MoveJ/Dwell` 式动作库。

### 6. 状态与证据

- 状态帧沿用通用几何路径状态帧 `0x05`，不新增车辆专用状态帧。字段为 `tick/kind/state/fault/s/t/x/z/dx/dz/kappa/speed/length`。
- 状态里必须能看出：周期、`s/t`、路径点、通道指令、反馈有无、故障。
- 没有反馈传感器时，只能写“开环指令验证”，不能写“轨迹跟踪成功”。
- 页面显示的状态必须来自内核状态，不得由页面自己推算。
- 页面可以用下发的 `LINE`/`ARC` 几何参数画一条琥珀色引导线，帮助看出命令形状；引导线不代表轨迹积分，车体位姿和轮角仍只来自 `0x05` 的路径点、切向、曲率和 `s`。

## 六、仿真边界

不是“完全不做仿真”，而是：

### 允许

- 3D 世界作为被控对象，接收内核指令、产生车辆运动、回传状态；
- 模型从文件加载，内核在环；
- 联调数据记录、回放、对比。

### 禁止

- 页面/宿主自己算转向、油门、目标，绕过内核；
- 内核掉线时，页面本地控制接管；
- 用 3D 联调截图当实车验收；
- 用仿真结果掩盖内核周期、限幅、故障、通道映射问题；
- 没有硬件却对外说“实车跑通”。

核心一句：**3D 世界可以当被控对象，不能当内核的替身。**

## 七、验收

### 模型格式与外观验收

- 模型文件能保存、能重新加载；
- 车壳、车轮、轴距、轮距、轮半径、离地间隙与文档一致；
- 模型不是代码里写死的几何；
- Forge 默认从 `interface/web/models/vehicle/toy_offroad.gltf` 加载，树里前轮是“转向枢轴 → 滚动轮胎 → 轮毂”，后轮是“滚动轮 → 轮毂”，共 6 个关节，其余节点显示为 part；
- 页面没有 `RUN / SWEEP / GRAB / SINE`、没有本地 PD，角度在未接内核时只读；
- 静态截图标注“静态外观模型”。

### 内核在环 3D 联调验收

- 模型从 `.gltf` / `.glb` 文件加载；
- 内核链路真实接通，HUD 显示内核状态，不是页面伪造；
- 键盘/手柄输入经内核产生转向/驱动，模型像车一样动；
- 页面没有本地控制兜底，断链能停；
- 复位、停车、限幅、超时都能工作；
- 记录里能区分“内核指令”和“3D 被控对象状态”。

### 硬件验收

- 只在 3D 联调验收通过后做；
- 真实转向、驱动、停车、断链、故障都要单独测；
- 不拿 3D 联调结果当实车证据。

## 八、需要操作者动手时必须提醒

这是开源项目文档，不假设只有原作者会操作。任何拿到模型、控制板或实车的人，都是现场操作者。

任何需要接电、接线、拆车、烧录、上电、架空轮子、落地测试的操作，必须先说明：

1. 要做什么；
2. 有什么风险；
3. 做到什么状态算完成；
4. 操作者确认后再继续。

操作者没有确认，不往下做。没有硬件，不拿软件替代。

## 九、停止条件

出现以下任一情况，停止并告知操作者：

- 模型还是代码里写死的，不是文件加载；
- 3D 世界里页面自己算控制，内核不在环；
- 内核掉线后页面本地接管；
- 拿 3D 联调截图当实车验收；
- 没有联调验收就要接硬件；
- 模型格式、通道映射、限位还没定，却要写控制代码；
- 想让页面逐周期算转向/油门，绕过内核控制任务。
